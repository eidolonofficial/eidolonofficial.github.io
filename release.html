Install from a terminal

Four ways in, one command block each

npm, the one-line way (Node 22 or newer, any system)

npx eidolon-hearth

It installs the two skills into your user folder, shows every path first and asks before it replaces anything. Inside a project, npx eidolon-hearth . also wires the project hooks. The package is eidolon-hearth on npm, version 0.1.1 since 14 October 2026. It ships the same bundles as the zip, checked against the same lock.

Windows, novice door (PowerShell 5.1, nothing else needed)

iwr -UseBasicParsing https://github.com/eidolonofficial/Hearth/releases/download/v0.1.1/Hearth-v0.1.1.zip -OutFile Hearth.zip
if ((Get-FileHash Hearth.zip -Algorithm SHA256).Hash -ne '0E4DD913A4EDD571DF0A4E35B7706054698C0BBE078464FDCE039F51C0DA70AA') { throw 'hash mismatch' }
Expand-Archive Hearth.zip -DestinationPath . -Force
powershell -NoProfile -ExecutionPolicy Bypass -File .\Hearth-v0.1.1\welcome.ps1

It downloads the zip, checks its SHA-256, unpacks it and runs the novice door. The door asks before it replaces anything.

macOS and Linux, novice door (bash)

curl -L -o Hearth.zip https://github.com/eidolonofficial/Hearth/releases/download/v0.1.1/Hearth-v0.1.1.zip
echo "0e4dd913a4edd571df0a4e35b7706054698c0bbe078464fdce039f51c0da70aa  Hearth.zip" | shasum -a 256 -c
unzip -q Hearth.zip && bash Hearth-v0.1.1/macos/Welcome.command

It downloads the zip, checks its SHA-256, unpacks it and runs the novice door. The door asks before it replaces anything.

Operator door, project hooks (Git and Node 22)

git clone --branch v0.1.1 --depth 1 https://github.com/eidolonofficial/Hearth.git
node Hearth/scripts/welcome.mjs

It clones the v0.1.1 tag of Hearth and runs the operator door. The door shows its plan and asks before it replaces anything.

Every door asks GitHub once for a newer Hearth release before it writes, and asks you before it acts on one. The npm route and the operator door need Node 22. The zip doors need nothing else.

Chapter 2

What shipped

  • Eidolon as a router skill with three modes: setup, build and autopilot
  • The native persona pipeline, with these parts:
    • agent files generated from the persona roster, with tools, model and effort
    • a write lane per worker
    • the brief gate
    • the dispatch log
    • SubagentStart and SubagentStop hooks
    • a wave plan before any swarm
    • a causal reasoning rail in every persona
  • The autopilot guide for loops, goals and routines, which opens with a brain dump and a chips interview
  • The engineering principles reference
  • A drift test that checks the hooks README against the code
  • A hardened installer: preview by default, apply bound to the digest of the previewed plan, a vendor lock, staged writes with rollback, and backups with receipts
  • Setup, which opens a session with the brain dump and asks only for what is missing
  • Hearth with two doors: a novice door with no Node and no hooks, and an operator door that needs Node 22 and wires the project hooks
Chapter 3

What was fixed

The PowerShell tool now reaches the shell guards. The release also fixes these shapes:

  • combined short flags such as -nm
  • a hooks path set through GIT_CONFIG_*
  • cd followed by a relative path
  • redirect and copy overwrites of records
  • path spellings that got past the record guards

The release wires the drift counter after each write. The dispatch matcher is Agent.

Chapter 4

What was removed

The release removes these parts from Eidolon:

  • the Codex adapter and the text written for two hosts
  • the vendored ASI-Evolve engine and evolve mode
  • the security-attestation and review-receipt ceremonies
  • the September persona-pipeline command line tools
  • the advisor, conduct, process-doctrine, security-surface and orient-gate hooks

It removes these parts from Hearth:

  • the three graphical installers: the Windows WPF window, the macOS app and the browser installer
  • Codex support
  • the optional tool cards
  • AGENTS.md

For Hearth, Git history keeps what the release removed.

Chapter 7

Live gates

The decision record names every round, gate and live test, and each open item with the check that settles it. G2 to G4 ran in headless Claude Code 2.1.206. They ran in a throwaway project after a real install, with hook debug logging on. Sandbox runs settled G1 and G5 later the same day.

G1, the novice door
With the user folder redirected to an empty one, 159 of 159 skill files landed byte for byte. The install wrote nothing else. A fresh session listed both skills. An old June copy in the user folder loaded ahead of the project copy. That copy is now in an archive, and the platform notes now say to keep one copy per machine.
G2, the guards
The hooks blocked git commit -n. They blocked a delete of a hook through the PowerShell tool, so the shell guard reaches PowerShell. The gate refused a dispatch with no Done-check: line. git push --force-with-lease passed the hook. Then the permission layer of Claude Code denied the push. That layer is separate from Eidolon.
G3, a dry run
/eidolon --dry-run produced the recon and the ten-stage plan, and it wrote nothing. It passed on the second try.
G4, the pipeline
The conductor wrote a wave plan. Then a builder agent ran on haiku with the lane src/**. The hooks blocked its writes outside the lane, and the dispatch log recorded it. The guard blocked a worker that tried to dispatch. A spawn depth of 1 did not remove the Agent tool from a worker. So the dispatch guard is the control that stops recursion.
G5, the interview
The brain dump, the reflect-back and the goal text all worked. The goal reached its end state. The interview guessed the permission choice and did not ask. The guide now forbids that.
The macOS doors
They ran on GitHub's macOS runner and under WSL Ubuntu.
Chapter 8

Still open

  • Claude Code's built-in /goal evaluator in an interactive session. Headless mode does not expand slash commands, so this needs a person.
  • A run of the doors on a user's own Mac.
  • Whether Claude Code itself refuses the spawn of a worker at depth 1. The dispatch guard blocks the call first, so no test shows this yet.
  • Whether the installer's Node 22 check runs before any syntax that an older Node rejects. A run under Node 20 settles this.

The hooks remain defense in depth. Their known gaps are the honest limit of what they cover.
