On the build

The persona pipeline

How one session conducts a company of named agents, from a spec you approve to a single commit.

In build mode, your main Claude Code session conducts. It plans, hands each piece of work to a named agent, checks the result against the files on disk, and makes the one commit at the end. All of it runs on Claude Code's own agents, hooks and settings.

Chapter 1The stages of a build

A build runs specify, plan, build, review, synthesize, verify, ship (only when the change deploys) and close. You approve the spec before work starts, the plan on standard or larger work, and the visual or runtime result at the end.

The verifier is a fresh agent that sees only the diff, the spec and the rubric. A third failed verify means the plan was wrong, so the plan is redone instead of fixed again. Only the close stage commits.

Chapter 2Agent files

Setup writes one file per persona into .claude/agents/, saying when to use that agent and giving it the fewest tools that do the job. Reviewers get Read, Grep, Glob and Bash; builders add Edit and Write. No agent gets the Agent tool, and the dispatch gate blocks a worker that tries to dispatch anyway.

Still open

In the live test, setting the spawn depth to 1 did not remove a worker's Agent tool, so the dispatch guard is the control that stops recursion. Whether Claude Code itself refuses a spawn at depth 1 has not been seen, because the guard blocks the call first.

Each file sets a model, an effort level and a turn limit. It carries the persona's mandate, its anchors (the named standards it works to), what it must never do, and the reasoning and brief sections below. Each must pass a lint script.

The session never dispatches a worker at its own tier. A brief may lower a worker's tier but never raise it above its agent file, and a failed leg moves one tier up before the plan is redone. Risk picks the tier, not the number of files. A dispatch that names no tier gets a question from the dispatch gate.

Chapter 4A wave plan before a swarm

Before the first agent that can write goes out, the conductor writes .claude/waves/<date>-<slug>.md. The plan names the result the wave is for, records a read-only inventory of what is really there, and lists the work items, each with its own write folder, its dependencies, its model and effort, and a done-check. It states the budget as arithmetic and names where you will be asked to decide. With no plan newer than the session start, the dispatch gate asks.

Chapter 5The brief

Every agent starts from a brief with the same parts: the goal in one sentence, the seated persona, the files it may touch, what it must not touch, the done-check, its budget, its model and effort, and a short prior of three to five hits from memory and the fix log. A brief for an agent that can write must carry the check on a line of its own:

Done-check: npm test exits 0

The line has to stand alone. In the live test on 2026-10-13, the first dispatch was refused because its done-check sat inside a sentence.

The agent returns one to two thousand tokens: the result first, then the evidence, the paths it changed, what it did not do and why, and the cause, falsifier and evidence for its main claim.

Chapter 6The dispatch log and the worker hooks

Every dispatch that is not blocked is appended to .claude/.dispatch-log.jsonl with the time, session, agent type, tier, effort, persona, write folders and a SHA-256 hash of the prompt. A log failure never stops the dispatch.

When a worker starts, the SubagentStart hook hands it its lane, a summary of the brief contract and its own line from the log. When it stops, the SubagentStop hook looks in its last message for evidence: a quoted span, an Evidence: line or a path that exists. With none, the worker is sent back once with the reason.

What this does not do

The stop check shows that the report names something real. It does not show that the done-check passed. The conductor still checks that.

Chapter 7Causal logic as a persona rail

Every persona, the conductor included, states each claim as a chain: the cause, the mechanism, the falsifier that would show it wrong, and the evidence it actually collected. A report missing a link is incomplete and says which link. The docs give an example for a QA lead:

Claim
The refund-cap test guards the cap.
Cause
The test sends an over-cap refund and expects a 422, so removing the cap check makes it fail.
Falsifier
A mutant that deletes the cap check leaves the test green.
Evidence
A mutation run on the cap check turns the test red, with the output pasted.

A persona with no named standard behind it fails the lint and is never seated. The docs call this rule "no anchor, no seat."

Chapter 8Review swarms

Personas staff each swarm, and each swarm must show its own check can fail before its pass is trusted.

Engineering
Builds. Each task's test must fail before the change and pass after it; a test that passes against nothing halts the run.
Code review
Simplifies without changing behavior. The suite passes the same way before and after, and a planted behavior change must make a test fail first.
Trust and safety
Checks harm, abuse, privacy, accessibility and fairness against GDPR, CCPA and WCAG 2.2 AA. A seeded line that logs personal data must be caught.
Security
Red finds and blue hardens. Each finding closes only when its fix is verified.
Ship and upload
Runs a deploy-readiness interview. A seeded missing environment variable or staged secret must block the ship.

Each review lens returns a score from 0 to 1, a pass or fail, and evidence. The score is the share of its checklist covered with evidence. It is not a pass mark: one blocker fails the lens whatever the score.

Chapter 9The engineering principles

These come from Anthropic's published engineering guidance and the Claude Code docs.

Workflows before agents

Use the simplest pattern that solves the task. One call with retrieval beats a chain, and a chain beats a swarm. A new agent, loop or index has to name the failure it removes.

Bounded loops

No loop runs without a check that ends it, a stop condition and a turn, time or attempt cap. Each pass reads real output, such as a test exit code or a diff, not its own claim. State goes to disk each pass so a restart resumes.

Retrieval

Fetch what a step needs when it needs it, and keep paths rather than file bodies. A corpus under about 200,000 tokens goes into context whole, with caching, and gets no index.

DAG waves

Write each wave as a dependency graph with separate write folders per node. Independent nodes start together. Use one agent for a lookup and three to five in parallel for research. Resume from the failed node, not from the start.

Graphs

Ask a code graph a structure question ("what calls this?") before reading files to answer it. The graph tools are optional; without one, setup falls back to search and read.

Context

Workers return short summaries with paths for detail. Each agent gets the minimum tools, with no two covering the same job. Notes live in files so they survive when context is trimmed.

Evaluation

Grade the end state, not the route taken. The verifier is a fresh agent told to refute the claim, given only the diff and the criteria. Show the command and its output rather than asserting a result.
