On autopilot, or the clockwork that keeps its word

Autopilot, or leaving a lamp lit

Loops, goals and routines, and the interview that comes before any of them runs.

Autopilot is for work that runs on its own. You start it with /eidolon loop, /eidolon goal or /eidolon routine. Plain words such as "keep doing this" or "check it every morning" also start it. Eidolon interviews you and picks a shape with you. It writes the run down, and it shows you how to stop it before anything starts.

Chapter 1

How the interview is built

The docs say that the interview is for a neurodivergent mind, and that it removes load and adds no steps. In practice, it works like this:

  • One question per screen.
  • You pick an answer from a few chips. You do not have to type.
  • Every question has skip and other.
  • There are no wrong answers. You can change any answer later.
  • No question has a timer. No question calls itself a "quick question."
  • Long, messy, jumping-around input is fine. Eidolon sorts it.
  • The recommended answer comes first, with a mark, so you have less to decide.
  • Eidolon says back what it heard before it acts.
  • Eidolon writes every answer to a file when you give it. You do not have to remember anything.

If the chip control is not available, Eidolon asks the same question in plain text with lettered options. Then it waits.

Chapter 2

The brain dump

The first screen is an invitation, and it is optional:

The screen offers three chips:

  • Start talking
  • Ask me questions instead
  • Skip

From what you say, Eidolon fills in a short record with these fields:

  • the outcome in your own words
  • who it is for
  • how you will know it is done
  • when it runs, and when it stops
  • what it must never do
  • the budget
  • what it reads
  • what annoys you about the current way
  • what is still open

A field that your dump does not cover stays empty.

Then it reflects back in under 10 lines. It starts with the words "Here is what I heard." You answer with one of three chips:

  • That's it
  • Fix something
  • Add more

Fix something asks one question per wrong line. It does not start over.

Chapter 3

Questions for the gaps

Eidolon asks only about the fields that are still empty. It never asks again about a field that your dump filled. It always asks about an empty field and never guesses. That rule also covers how to handle permission prompts when no one watches. The rule came after the live test on 2026-10-13. In that test, the interview filled in the permission choice and did not ask.

The questions it may ask are these:

  • which shape fits
  • how you will know it is done
  • how often it runs
  • when it stops
  • what it must never do
  • how to handle permission prompts

For permission prompts, the recommended answer is an allowlist of the commands it needs. The other choice is auto mode.

Chapter 4

The four shapes

Four ways to leave something running, and how to stop each one
ShapeUse it whenLimitsTo stop it
Goal There is a clear finish line. This is the recommended shape when there is one. It runs in your session. After every turn, a small fast model checks the condition. It reads only what Claude printed. So the output of the check has to appear in the conversation. No cadence. /goal clear
Loop Something repeats on an interval, or at its own pace. It runs in your session, and only while the session is open and idle. The minimum interval is 1 minute. The fire time can shift by a few minutes. It stops on its own after 7 days. Esc, or CronDelete
Routine It runs in the cloud with no one there. A schedule, an API call or a GitHub event starts it. The minimum interval is 1 hour. It runs on a fresh clone and cannot read your local files. If your inputs are local, Eidolon steers you to one of the other shapes. Change it with /schedule update
Desktop task It needs your local files and runs on a schedule. It runs on your machine, so the machine must be on. Disable it in the scheduled tasks list

For a loop, a routine or a desktop task, one cadence chip is Daily at 9:07. A time off the hour avoids the jitter on the hour.

Chapter 5

What gets written, and the yes

Eidolon shows you the exact text it will use, and the instruction that stops it. Then it waits for your yes. It creates nothing before that.

.claude/autopilot/<slug>.md
What Eidolon created, why, and how to stop it. Eidolon writes this file before the run starts, so the stop instruction is on disk first.
.claude/session.yaml
Your answers from the interview.

After it creates the goal, loop or routine, Eidolon reads it back from Claude Code. Then it shows it to you.

Chapter 6

What a goal looks like

This is the example from the autopilot guide:

/goal All tests in `npm test` pass and `npm run lint` exits 0. After each change,
run both and print the last 5 lines of output. Do not edit files under
`migrations/`. Stop after 20 turns.

It has four parts:

  • one end state you can measure
  • a check whose output shows up in the conversation
  • a named thing it must not change
  • a turn cap

Every prompt that Eidolon writes for autopilot follows those rules. It states the task, paths and tools in full. The run cannot ask you a question later.

Chapter 7

What has been tested

On 2026-10-13 the interview ran headless over three turns. It offered the brain dump and reflected back. Then it wrote a goal with these parts:

  • one end state
  • the check, printed in full
  • two things it must never do
  • a six-turn cap

Both files landed. With its own cap, that goal reached its end state in one turn. It left docs/ untouched.

Still open

The built-in /goal evaluator of Claude Code still needs a manual run in an interactive session. Headless mode does not expand slash commands, so that check needs a person.
