On autopilot

Autopilot, or leaving a lamp lit

Loops, goals and routines, and the interview that comes before any of them runs.

Autopilot is for work that should run on its own. You start it with /eidolon loop, /eidolon goal or /eidolon routine, or in plain words such as "keep doing this" or "check it every morning." Eidolon interviews you, picks a shape with you, writes the run down, and shows you how to stop it before anything starts.

Chapter 1How the interview is built

The docs say the interview is built for a neurodivergent mind, and that it removes load instead of adding steps. In practice:

  • One question per screen.
  • You pick an answer from a few chips. Typing is optional.
  • Every question has skip and other.
  • There are no wrong answers, and any answer can be changed later.
  • Nothing is timed, and nothing is framed as a "quick question."
  • Long, messy, jumping-around input is fine. Eidolon sorts it.
  • The recommended answer is listed first and marked, so you have less to decide.
  • Eidolon says back what it heard before it acts.
  • Every answer is written to a file when you give it, so nothing has to be remembered.

If the chip control is not available, Eidolon asks the same question in plain text with lettered options and waits.

Chapter 2The brain dump

The first screen is an invitation, and it is optional:

The chips are Start talking, Ask me questions instead and Skip. From what you say, Eidolon fills in a short record: the outcome in your own words, who it is for, how you will know it is done, when it runs, when it stops, what it must never do, the budget, what it reads, what annoys you about the current way, and what is still open. A field your dump did not cover stays empty.

Then it reflects back, in under 10 lines, starting with "Here is what I heard." You answer with That's it, Fix something or Add more. Fix something asks one question per wrong line. It does not start over.

Chapter 3Questions for the gaps

Eidolon asks only about the fields that are still empty. A field your dump filled is never asked again. An empty field is always asked and never guessed, including how to handle permission prompts when no one is watching. That last rule was added after the live test on 2026-10-13, where the interview filled in the permission choice instead of asking.

The questions it may ask: which shape fits, how you will know it is done, how often it runs, when it stops, what it must never do, and how to handle permission prompts. For that last one the recommended answer is an allowlist of the commands it needs; the other choice is auto mode.

Chapter 4The four shapes

Four ways to leave something running, and how to stop each one
ShapeUse it whenLimitsTo stop it
Goal There is a clear finish line. This is the recommended shape when there is one. Runs in your session. After every turn, a small fast model checks whether the condition is met. It reads only what Claude printed, so the check's output has to appear in the conversation. No cadence. /goal clear
Loop Something should repeat on an interval, or at its own pace. Runs in your session, and only while it is open and idle. The minimum interval is 1 minute. Firing can shift by a few minutes. It stops on its own after 7 days. Esc, or CronDelete
Routine It should run in the cloud with no one there, on a schedule, an API call or a GitHub event. The minimum interval is 1 hour. It runs on a fresh clone and cannot read your local files. If your inputs are local, Eidolon steers you to one of the other shapes. Change it with /schedule update
Desktop task It needs your local files and should run on a schedule. Runs on your machine, so the machine must be on. Disable it in the scheduled tasks list

For a loop, a routine or a desktop task, one of the cadence chips is "Daily at 9:07." A time off the hour avoids the jitter on the hour.

Chapter 5What gets written, and the yes

Eidolon shows you the exact text it will use and the instruction that stops it. Then it waits for your yes. Nothing is created before that.

.claude/autopilot/<slug>.md
What was created, why, and how to stop it. This file is written before the run starts, so the stop instruction is on disk first.
.claude/session.yaml
Your answers from the interview.

After creating the goal, loop or routine, Eidolon reads it back from Claude Code and shows it to you.

Chapter 6What a goal looks like

This is the example from the autopilot guide:

/goal All tests in `npm test` pass and `npm run lint` exits 0. After each change,
run both and print the last 5 lines of output. Do not edit files under
`migrations/`. Stop after 20 turns.

It has one end state you can measure, a check whose output shows up in the conversation, a named thing it must not change, and a turn cap. Every prompt Eidolon writes for autopilot follows those rules. It states the task, paths and tools in full, because the run cannot ask you a question later.

Chapter 7What has been tested

On 2026-10-13 the interview ran headless over three turns. It offered the brain dump, reflected back, and wrote a goal with one end state, the check printed in full, two things it must never do and a six-turn cap. Both files landed. Run with its own cap, that goal reached its end state in one turn and left docs/ untouched.

Still open

Claude Code's built-in /goal evaluator has not yet been run by hand in an interactive session. Headless mode does not expand slash commands, so that check needs a person.
