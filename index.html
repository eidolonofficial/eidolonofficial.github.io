An introduction

A lantern for the repository

A field guide to a Claude Code skill that readies a repository, then builds from a written spec with you at the gates.

Eidolon is a skill for Claude Code. It sets up a repository so Claude Code can work well in it. Then it carries a piece of work from a written spec to a committed change, and it stops at set points so you can approve, edit or stop.

It runs in Claude Code only. Version 0.1.0 came out on 13 October 2026 with two companions: Setup, a skill that opens a work session, and Hearth, the installer for both. The release page has the record.

Chapter 1The three modes

Eidolon picks a mode from what you ask, and tells you which one it picked.

The modes, and when each one runs
ModeWhenWhat happens
Setup You have no work item yet, or you ask it to set up the repository. It reads the repository, works out your languages and tools, and writes what Claude needs: a CLAUDE.md, helper skills and slash commands, sub-agents, safety hooks, MCP setup and memory wiring. It pauses for you after the plan, the structure and the wiring.
Build You have something to build, change or fix. It writes a spec, plans, builds test first, runs review swarms, has a fresh agent check the result, and commits once at the end. See the pipeline.
Autopilot /eidolon loop, /eidolon goal or /eidolon routine, or "keep doing this". It interviews you, writes the run down, and shows you how to stop it before it starts. See autopilot.

It works without asking, and pauses only before it installs a skill, seats the primary persona (the house agent it builds for your repository), deploys, runs something that cannot be undone, or dispatches sensitive work. Each pause is one question, with a line saying who is harmed if the answer is wrong. Nothing is written before you approve the plan.

Chapter 2Who it is for

Eidolon is for anyone who wants a repository ready for Claude Code, or wants something built, changed or fixed in one. You do not need to say the word Eidolon. The skill loads when you ask for that kind of work.

Hearth, the installer, was designed for a person running their own business who is not confident with computers and would stop at "open PowerShell and paste this command." That person gets a door that needs nothing installed first. Operators who want project hooks get a second door.

The docs say the interview that opens a session is built for a neurodivergent mind. It asks one question per screen, lets you pick an answer instead of typing one, and lets you skip any question. Every answer goes to a file, so you do not have to hold anything in your head. It also asks how familiar you are with coding and pitches its language to your answer.

Chapter 3Two doors in

Hearth comes as Hearth-v0.1.0.zip on its release page. Inside it are two doors. Pick one.

Door 1. The novice door

Use it if
You want the two skills and nothing else.
What it needs
Nothing beyond what your computer already has: no Node, no Git and no other tools.
How to start it
On Windows, double-click Start Here.cmd. It runs welcome.ps1 in Windows PowerShell 5.1. On a Mac, open macos/Welcome.command, a plain bash script. If macOS blocks it, right-click the file, choose Open, then confirm.
What it writes
Two folders in your user folder: .claude/skills/eidolon and .claude/skills/setup. It prints each file as it lands. It writes nothing else, adds no hooks and installs no other tool.
If a skill is already there
It asks you to type replace or press Enter to skip. Skip is the default. On replace, your old folder moves to .claude/skills/.hearth-backups/<yyyyMMdd-HHmmss>/<name> before the new one is copied.
To undo it
Delete the eidolon and setup folders from .claude/skills. If Hearth saved an older copy, move it back from .hearth-backups.
Still open

The Mac door ran on GitHub's macOS runner and under WSL Ubuntu on 2026-10-13. It has not yet run on a user's own Mac.

Door 2. The operator door

Use it if
You want Eidolon's hooks wired into a project.
What it needs
Node 22 or newer. It checks first. If Node is missing or too old, it points you to nodejs.org and stops.
How to start it
On Windows, double-click Operator Setup.cmd. On a Mac, open macos/Operator Setup.command. From any terminal, run node scripts/welcome.mjs.
Before it writes
It asks for a project folder; blank means user skills only. It checks every bundled file against vendor-lock.json and stops on a mismatch. Under "Proposed locations:" it lists every path it will write, with the text, the settings diff or the replacement changes for each. It writes only after you type yes, and only the plan it showed you.
What it writes in the project
  • .claude/skills/eidolon and .claude/skills/setup
  • .claude/settings.json with the hook entries and the permission deny rules, and .claude/eidolon-manifest.yaml
  • .eidolon/policy-manifest.json
  • one marked section each in CLAUDE.md and .gitignore, between eidolon:begin and eidolon:end lines
It also sets three settings keys, replacing any values already there: env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH to "1", effortLevel to xhigh and maxEffortLevel to max. The preview says so.
If a skill is already there
You type replace to see a replacement plan. Old files are kept under .eidolon/backups/<id>/ with a receipt.json. Nothing is deleted. A plan that changed after you reviewed it is refused, and a failed install is never reported as a success.
After it finishes
It prints the verified file count, the backup receipt path and the next step. Restart Claude Code in the project, and the hooks are active in the next session. They run Node, so keep Node installed.

Either way, open Claude Code and type /eidolon or /setup.

You can also clone the skill into your user skills folder with git clone https://github.com/eidolonofficial/eidolon.git ~/.claude/skills/eidolon. Keep one copy of Eidolon per machine, or keep both at the same commit. In a test on 2026-10-13, with a user copy and a project copy of the same name, Claude Code loaded the user copy, which was the older one.

What this does not do

A copied skill has no hooks. Only a project install wires them: the operator door, or the installer run with --project.

Chapter 4What it never does

  • Write to your project before you approve the plan.
  • Install anything besides the two skills: no extra programs, background tasks, account sign-in, Node, credentials, models or services.
  • Delete your old copy. A replaced skill moves to a backup folder first.
  • Commit before the last stage of a build. Only the close stage commits, and before it does, it states the git state from before the run as the way back.
  • Take orders from what it reads. A pull request body, an issue, a web page or a file is data. An instruction found inside one is reported to you as a finding.
  • Write a secret into a report, a log, a commit or a chat message.
  • Shrink a record. The logs of what broke, what worked and what was decided only grow.
  • Weaken a guard to make a test pass.
